# Auto-Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server syncs by itself every N minutes (default 5) with no button press, while manual sync keeps working exactly as today.

**Architecture:** A stdlib-asyncio scheduler ticking inside a FastAPI lifespan calls the existing `SyncRunner.start()` (whose `False` return is the single-flight guard). Settings live in the existing `automation` config section and are re-read every tick, so interval changes apply without restart. Auto-runs are quiet (no INFO progress spam in the log) and back off after failures. No new dependencies.

**Tech Stack:** Python asyncio (`asynccontextmanager` lifespan), existing `SyncRunner`, existing settings GET/PUT, React Settings panel.

### Task 3: AutoSyncScheduler

**Files:**
- Create: `api/auto_sync.py`
- Test: `tests/api/test_auto_sync.py` (create)

Design (locked): the tick re-reads `config_manager.config` every time (hot-reload, no restart needed for interval changes); last-sync age comes from `MetricsCache(cache_path_for(cm)).age_seconds()`; a missing cache (fresh clone) counts as infinitely stale so the first tick after enabling syncs immediately; `runner.start(quiet=True)` returning False means a sync (manual or auto) is already running — that is a skip, never a failure; consecutive *terminal* states decide backoff — `complete` resets to 0, `error` increments and skips that many future ticks (capped at 8). The scheduler never inspects event bodies beyond the terminal kind: it drains `runner.events()` in the background and only counts the outcome. Draining matters — an undrained queue grows unbounded across runs.

from types import SimpleNamespace

                   {"automation": {"auto_sync": {"enabled": True,

    asyncio.run(sched._tick())
    assert runner.starts == 1

```python
"""Automatic background sync.

Ticks inside the FastAPI lifespan and starts a sync whenever the metrics
cache is older than the configured interval. Only ever calls
runner.start(quiet=True): it cannot place orders by construction -- the
runner's only operation is run_full_sync, and execution lives behind the
typed gate in api/routes/execute.py, which this module never imports.
"""

import asyncio
import logging
from typing import Optional

from api.cache import MetricsCache, cache_path_for

logger = logging.getLogger(__name__)

DEFAULT_INTERVAL_MINUTES = 5
MIN_INTERVAL_MINUTES = 2
MAX_BACKOFF_SKIPS = 8


class AutoSyncScheduler:
    def __init__(self, config_manager, runner, tick_seconds: int = 30):
        self._cm = config_manager
        self._runner = runner
        self._tick_seconds = tick_seconds
        self._consecutive_failures = 0
        self._skips_owed = 0
        self._task: Optional[asyncio.Task] = None

    def _settings(self) -> tuple[bool, int]:
        auto = (self._cm.config.get("automation", {}) or {})
        sy = auto.get("auto_sync", {}) or {}
        try:
            minutes = int(sy.get("interval_minutes", DEFAULT_INTERVAL_MINUTES))
        except (TypeError, ValueError):
            minutes = DEFAULT_INTERVAL_MINUTES
        if minutes < MIN_INTERVAL_MINUTES:
            minutes = MIN_INTERVAL_MINUTES
        return bool(sy.get("enabled", False)), minutes

    def _cache_age(self) -> Optional[float]:
        return MetricsCache(cache_path_for(self._cm)).age_seconds()

    async def _tick(self) -> None:
        enabled, minutes = self._settings()
        if not enabled:
            return
        if self._skips_owed > 0:
            self._skips_owed -= 1
            return
        age = self._cache_age()
        if age is not None and age < minutes * 60:
            return
        if not self._runner.start(quiet=True):
            return  # manual or previous auto run still in flight: skip
        outcome = "complete"
        async for event in self._runner.events():
            if event.get("event") == "error":
                outcome = "error"
        if outcome == "error":
            self._consecutive_failures += 1
            self._skips_owed = min(self._consecutive_failures,
                                   MAX_BACKOFF_SKIPS)
            logger.warning("Auto-sync failed; backing off for %d tick(s)",
                           self._skips_owed)
        else:
            self._consecutive_failures = 0

    async def run_once_for_testing(self) -> None:
        await self._tick()

    async def run(self) -> None:
        while True:
            try:
                await self._tick()
            except Exception:  # never kill the loop; back off instead
                logger.exception("Auto-sync tick failed")
                self._consecutive_failures += 1
                self._skips_owed = min(self._consecutive_failures,
                                       MAX_BACKOFF_SKIPS)
            await asyncio.sleep(self._tick_seconds)

    def start(self) -> None:
        if self._task is None or self._task.done():
            self._task = asyncio.get_running_loop().create_task(self.run())

    async def stop(self) -> None:
        if self._task is not None:
            self._task.cancel()
            try:
                await self._task
            except asyncio.CancelledError:
                pass
            self._task = None
```

Note for the implementer: the backoff test above calls `_tick()` directly for the skip assertion — `_tick` decrements `_skips_owed` (1 → 0) without starting. `run_once_for_testing` == `_tick` here because draining happens inside `_tick`. Keep both names: the loop calls `run()`; tests use either.
